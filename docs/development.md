# 开发任务与验收

## 当前已完成

- 前后端、测试、数据和文档目录。
- 环境变量读取与占位配置样例。
- 同源页面、健康检查、聊天请求校验和明确的待实现响应。
- 工具、模型、执行器和会话存储的代码入口。

## 下一步顺序

1. 确定一个专业子方向和可分发样本，填写测试输入与预期；补充用户时间、算力和数据条件。
2. 实现论文解析工具，输出可核对的原文依据；正常、无效输入分别测试。
3. 选择论文检索数据源，记录凭据、限流、超时与失败行为；将解析结果实际传入检索参数。
4. 实现模型适配和智能体循环：信息不足时追问；工具参数先校验；前一步成功返回后再构造依赖参数；限制步数与重试，记录请求标识和调用轨迹。
5. 实现会话存储，验证追问、更正覆盖、历史裁剪和会话隔离。
6. 加入可行性规则，完善研究方案展示与错误后继续讨论的交互。

## 业务验收案例（待实现后执行）

| 输入或操作 | 预期行为 | 证据 |
| --- | --- | --- |
| 仅提供宽泛方向 | 针对缺失条件追问，不编造已读论文 | 回复及状态变化 |
| 提供可解析论文 | 提取问题、方法与实验设置，标注依据 | 原文对照与工具输出 |
| 解析后检索 | 查询参数包含实际解析出的信息 | 两次工具实参和返回值 |
| 将 GPU 条件更正为仅 CPU | 后续参数使用新约束，重新评估方案 | 状态差异与调用日志 |
| 会话 B 未提供 A 的方向 | 不读取 A 的事实；切回 A 可继续 | 两个会话的脱敏状态 |
| 检索无结果或超时 | 区分无结果和失败，允许补充条件或重试 | 错误返回与执行轨迹 |

论文原文、个人会话和日志放在对应数据目录；可共享的脱敏测试样本放在 `data/samples`。不得在样例或日志中写入真实模型密钥。
